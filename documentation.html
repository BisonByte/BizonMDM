BizonMDM — Libro de instalación, configuración y uso

Este documento es la referencia completa para desplegar y operar BizonMDM: servidor/API, panel de administración web y aplicación Android para administración de dispositivos móviles (MDM). Incluye pasos detallados para VPS (Linux), Windows y Docker.

Repositorio

BisonByte/BizonMDM

Áreas: Servidor (Python), Admin Frontend (JS), App (Kotlin)

Estado rápido

  • Instalador web del servidor en /install
  • Migraciones con Alembic
  • Soporte de FCM para notificaciones

Licencia

Consulte el archivo LICENSE en el repositorio.

Arquitectura & componentes

BizonMDM se compone de tres piezas principales:

  • Servidor (API) — Python (SQLAlchemy/Alembic). Expone endpoints REST como /api/status, maneja autenticación JWT y conexión a la base de datos.
  • Panel Admin — UI web en admin-frontend/ para listar dispositivos, enviar acciones (bloqueo, borrado, etc.) y ver estado del sistema.
  • App Android — Cliente MDM (Kotlin) que se comunica con el servidor y recibe notificaciones via Firebase Cloud Messaging (FCM).

Requisitos

  • Servidor: Python 3.10+, pip, opcional Docker 24+, Docker Compose. Base de datos SQL (PostgreSQL, MySQL/MariaDB o SQLite para pruebas).
  • Panel: navegador moderno; si desea construir el frontend, Node.js 18+ recomendado.
  • App Android: Android Studio (Giraffe+), SDK 24+, dispositivo físico o emulador.
  • Notificaciones: un proyecto de Firebase con clave de servidor FCM.

Arranque rápido (local)

  1. Clone el repositorio:
git clone https://github.com/BisonByte/BisonMDM && cd BizonMDM
  1. Instale dependencias del servidor e inicie el instalador:
pip install -r server/Servidor/requirements.txt
python server/install_script.py
  1. Abra http://localhost:5000/install y complete el formulario con la cadena de conexión de BD, clave JWT, clave de FCM y un usuario admin inicial.
  2. Tras finalizar, arranque el servidor:
python server/Servidor/server.py
  1. (Opcional) Construya el panel de administración si modificó la interfaz:
cd server/admin-frontend
npm install
npm run build
  1. Verifique el estado de la API:
curl http://localhost:5000/api/status

Opciones de instalación

Instalación en VPS (Ubuntu/Debian)

  1. Actualice el sistema y dependencias:
sudo apt update && sudo apt -y upgrade
sudo apt -y install python3 python3-pip python3-venv git
  1. Clone y configure entorno:
git clone https://github.com/BisonByte/BizonMDM && cd BizonMDM
python3 -m venv .venv && source .venv/bin/activate
pip install -r server/Servidor/requirements.txt
  1. Ejecute el instalador y complete /install:
python server/install_script.py
  1. Inicie el servidor en segundo plano (opción simple):
nohup python server/Servidor/server.py & disown

Producción recomendado: usar gunicorn + systemd y un proxy inverso Nginx.

Ejemplo con gunicorn + systemd 
# Instalar gunicorn
pip install gunicorn

# Servicio systemd (bizonmdm.service)
[Unit]
Description=BizonMDM API
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/BizonMDM
Environment="PATH=/opt/BizonMDM/.venv/bin"
ExecStart=/opt/BizonMDM/.venv/bin/gunicorn -w 3 -b 0.0.0.0:5000 Servidor.server:app
Restart=always

[Install]
WantedBy=multi-user.target

Instalación en Windows 10/11

  1. Instale Python 3.10+ (Add to PATH) y Git.
  2. Abra PowerShell como Administrador y ejecute:
git clone https://github.com/BisonByte/BizonMDM; cd BizonMDM
python -m venv .venv; .venv\Scripts\Activate.ps1
pip install -r server/Servidor/requirements.txt
python server/install_script.py

Abra http://localhost:5000/install, complete el formulario y después ejecute:

python server/Servidor/server.py
Servicio en segundo plano con NSSM (opcional)

Instale NSSM y cree un servicio apuntando a python.exe con el script server/Servidor/server.py.

Instalación con Docker Compose

  1. Instale Docker Desktop (Windows) o Docker Engine (Linux) con Compose.
  2. Desde la carpeta server/:
cd server\ndocker compose up -d

Revise y adapte variables de entorno en server/docker-compose.yml y/o archivo .env según su base de datos y claves.

Configuración del Servidor (API)

  • Instalador web: /install crea .env, guarda la clave FCM y ejecuta migraciones (Alembic).
  • Variables principales:
    • DATABASE_URL — cadena de conexión (PostgreSQL, MySQL/MariaDB o SQLite).
    • JWT_SECRET — clave secreta para firmar tokens.
    • FCM_SERVER_KEY — clave de servidor de Firebase Cloud Messaging.
    • ADMIN_EMAIL, ADMIN_PASSWORD — usuario inicial.
    • API_BASE_URL — URL pública si usa proxy (ej.: https://mdm.midominio.com).
  • Comprobación de salud: /api/status valida DB y FCM.

Configuración del Panel de Administración

La UI vive en admin-frontend/. Puede servirse como estática detrás de Nginx o construirse si el proyecto incluye herramientas de build.

Opción A — Servir como estático 
sudo apt -y install nginx
sudo cp -r admin-frontend /var/www/bizonmdm
# Config Nginx (bloque de servidor)
server {
  server_name mdm.midominio.com;
  root /var/www/bizonmdm;
  location / { try_files $uri $uri/ /index.html; }
  location /api/ { proxy_pass http://127.0.0.1:5000/; }
}
Opción B — Construir (si hay package.json) 
cd admin-frontend
npm ci || npm install
npm run build
# despliegue del directorio de build en su servidor web

Configuración de la App Android

  1. Abra app/ con Android Studio.
  2. Configure las constantes de servidor (ej.: BASE_URL) y FCM según el archivo de configuración del proyecto (por ejemplo, BuildConfig o recursos strings.xml).
  3. Conecte su proyecto Firebase y asegúrese de que el Sender ID/clave coincidan con el servidor.
  4. Ejecute las pruebas con ./gradlew test connectedAndroidTest para validar la aplicación.
  5. Construya e instale en el dispositivo (Run ▶ o Build APK).

Notificaciones (Firebase Cloud Messaging)

  1. En Firebase Console cree un proyecto o use uno existente.
  2. Obtenga la clave del servidor (FCM) y colóquela durante el paso de /install o en .env como FCM_SERVER_KEY.
  3. Desde la app Android, asegúrese de registrar el token FCM del dispositivo contra el servidor.

Base de datos

BizonMDM usa SQLAlchemy y migraciones con Alembic. Ejemplos de cadenas de conexión:

# PostgreSQL
DATABASE_URL=postgresql+psycopg2://usuario:pass@localhost:5432/bizon
# MySQL/MariaDB
DATABASE_URL=mysql+pymysql://usuario:pass@localhost:3306/bizon
# SQLite (pruebas)
DATABASE_URL=sqlite:///bizon.db

Almacenamiento de archivos (opcional)

Si su despliegue requiere subir/servir archivos (logs, adjuntos, etc.), puede usar proveedores S3-compatibles como Filebase o sistemas locales. Configure variables como S3_ENDPOINT, S3_BUCKET, S3_KEY, S3_SECRET según su elección.

Si en su proyecto se usa Firebase Storage en lugar de S3/Filebase, indique las credenciales en la sección de App Android y el servidor deberá firmar URLs según su flujo.

Uso del panel

  1. Inicie sesión con el usuario administrador creado.
  2. Verifique el indicador de estado (DB y FCM) que consulta /api/status.
  3. Registre dispositivos (alta) y asigne políticas.
  4. Ejecute acciones: Bloquear dispositivo, Borrar datos, etc.

Gestión de dispositivos

  • Alta: instale la app, inicie sesión y permita permisos requeridos (administrador del dispositivo, notificaciones, accesibilidad si aplica).
  • Sincronización: el dispositivo reporta estado periódico y recibe órdenes vía FCM + pull de API.
  • Baja: desinscribir desde el panel o restablecer de fábrica el dispositivo.

Gestión de usuarios y autenticación

El servidor expone endpoints para crear cuentas, iniciar sesión y controlar permisos.

Creación de usuarios

curl -X POST https://mi-servidor/api/users \
  -H "Authorization: Bearer <token_admin>" \
  -H "Content-Type: application/json" \
  -d '{"username":"jane","password":"secreta","role":"cliente"}'

Inicio de sesión

curl -X POST https://mi-servidor/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"jane","password":"secreta"}'

Permisos y roles

Los roles admin, operador y cliente delimitan el acceso a módulos y endpoints.

Panel cliente

Tras autenticarse, los usuarios acceden al panel en /cliente para gestionar sus dispositivos.

Ejemplo: listar dispositivos

curl -H "Authorization: Bearer <token_cliente>" https://mi-servidor/api/devices

Acciones sobre un dispositivo

curl -X POST https://mi-servidor/api/devices/42/lock \
  -H "Authorization: Bearer <token_cliente>"

Consideraciones de seguridad

  • Requiere HTTPS y tokens JWT válidos.
  • Las contraseñas se guardan con hash seguro (bcrypt).
  • Revoca tokens comprometidos y usa expiración corta.
  • Deshabilita el instalador /install tras la configuración.
  • Limita intentos de inicio de sesión para mitigar fuerza bruta.

Seguridad

  • Use HTTPS en producción con certificados válidos (Let’s Encrypt).
  • Guarde JWT_SECRET y FCM_SERVER_KEY en secreto.
  • Conceda mínimos privilegios al usuario de la base de datos.
  • Habilite registros y rotación de logs. Considere WAF/Fail2ban.

Backups & actualización

  1. Base de datos: snapshots diarios + retención (p. ej., 7/30/180 días).
  2. Archivo .env y claves FCM: copie a un almacén seguro.
  3. Actualización: cree respaldo, obtenga últimos cambios (git pull), aplique migraciones (alembic upgrade head si corresponde) y reinicie servicios.

Solución de problemas

El instalador /install falla al guardar .env

Verifique permisos de escritura en la carpeta del proyecto y ejecute el proceso con un usuario con privilegios adecuados.

/api/status indica error de DB

Revise DATABASE_URL y que la instancia esté accesible desde el servidor. Compruebe credenciales y puertos.

Notificaciones no llegan al dispositivo
  • Confirme la FCM_SERVER_KEY.
  • Verifique que la app registre y envíe el token al servidor.
  • Revise que el dispositivo tenga internet y no tenga restricciones de batería para la app.

Preguntas frecuentes

¿Qué base de datos recomiendan en producción?

PostgreSQL por estabilidad y compatibilidad. MySQL/MariaDB también es soportado. SQLite solo para pruebas.

¿Puedo desplegar todo con Docker?

Sí. Ajuste variables en server/docker-compose.yml y ejecute cd server && docker compose up -d.

¿La app Android funciona sin FCM?

Algunas funciones que requieren push dependerán de FCM. Puede usar sólo pull periódico, con menor inmediatez.

Glosario

  • FCM: Firebase Cloud Messaging, servicio de notificaciones push.
  • JWT: JSON Web Token para autenticación.
  • Alembic: herramienta de migraciones de bases de datos para SQLAlchemy.
